# ВОиАД · Лабораторная работа №2

**Тема:** разработка процессов преобразования и представления данных.
**Страница:** «Анализ и сопоставление данных» (`music_app/app/views/compare.py`), подключена в `music_app/app/main.py`.
Расчёты вынесены в модули без Streamlit: `modules/monitor.py` (SQL), `modules/compare_data.py` (pandas), `modules/transfer.py` (две СУБД).
Страница ЛР1 «Исследовательский анализ» не изменялась.

## Что реализовано

| Требование задания | Раздел страницы |
|---|---|
| Общие показатели состояния хранилища | 1. Общие показатели |
| Записи в SOURCE, STAGING, ODS; таблицы и графики | 2. Слои, таблица по партиям и график |
| Причины изменения числа записей после очистки | 2. Диаграмма «водопад» STAGING → ODS по `ods.dq_log` |
| Строки DWH с учётом гранулярности | 2. Таблица «DWH и уровень детализации» (факты = ODS, измерения ≥ distinct) |
| Качество до и после очистки | 3. Замер по STAGING и ODS, сверка с журналом, график долей |
| Отклонённые записи (по сохранённому журналу) | 3. `ods.dq_reject`: причины и примеры |
| Объёмы по `dt` | 4. Динамика по дням / неделям / месяцам, по слоям или партиям |
| Исходные и синтетические данные: заполненность, уникальность, аномалии | 5. Таблица профиля (общая и по партиям) |
| Распределения числовых и категориальных признаков | 5. Выбор признака, доли, расстояние полной вариации (TVD) |
| Витрина на основе DWH | 6. Показатели, группировки, сверка с фактами |
| Итоговые выводы | 7. Формируются из фактических результатов |
| Проверка согласованности витрин в двух СУБД | 8. Таблица показателей, построчное сравнение, сравнение по датам |
| Интерактивность и фильтры по `dt` и партиям | боковая панель: партии, период `dt`, Топ-N, детализация |

## Как устроена проверка согласованности

Для каждого показателя в таблице: наименование, способ расчёта, значение в PostgreSQL, значение в целевой СУБД,
расхождение, допуск, результат и вывод. Показатели считаются одним и тем же запросом в обеих СУБД за выбранный период.
Целочисленные показатели сравниваются строго, дробные (`Decimal` ↔ `float`) — с допуском 1e-6. Дополнительно строки двух витрин
сопоставляются по ключу (`dt`, город, жанр): строки только в одной СУБД, расхождения значений, сравнение по датам.

Количество исправленных и отклонённых записей берётся из `ods.dq_log` / `ods.dq_reject`, которые пишет сама `ods.load_ods()`.
Заготовленных значений на странице нет.

## Запуск

```
pipenv run streamlit run music_app/app/main.py
```
Данные загружаются командами `music_app/cli.py` (см. [АБД ЛР2](../../bda/lab02/README.md)); кнопка «Обновить данные» в боковой панели сбрасывает кэш.
